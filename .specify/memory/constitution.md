# a-default-project Constitution

## Core Principles

### I. Template-as-Code

The template repository IS code — it is not documentation, not a wiki, and not a bag of starter files.
All structural changes, profile additions, agent updates, and scaffold logic changes MUST be tracked as
code commits. The `SPECKIT_SYNC_DATE` constant in `scripts/lib/config.py` MUST be updated (manually,
to a human-readable `YYYY-MM-DD` string) on every release that alters generated output.

**Rules:**
- Every change to `.github/agents/`, `.github/prompts/`, or `.specify/templates/` requires a
  `SPECKIT_SYNC_DATE` bump and a corresponding changelog entry.
- The template version is the single source of truth for what child projects inherit at scaffold time.
- Structural decisions (D-01…D-nn) MUST be recorded in session debate files before implementation.

### II. SpecKit-First

AI-assisted development is the **default workflow** for every project generated by this template —
not an optional add-on. Every child project MUST receive the full SpecKit agent and prompt set
(`.github/agents/speckit.*.agent.md`, `.github/prompts/`) as part of scaffolding.

**Rules:**
- `scaffold.py` MUST always copy SpecKit agents and prompts regardless of domain profile selection.
- The `devops-security` domain profile is always included (transversal, non-negotiable — see D-20).
- Question [8] in the interactive flow governs additional profile selection: [1] domain-only,
  [2] all profiles, [3] manual select (see D-21).
- Constitution and domain profiles MUST be generated in the same scaffold session (see D-22).

### III. Scaffold Idempotente

Running `scaffold.py` multiple times against the same target directory MUST be safe. No file is
silently overwritten, no directory entry is duplicated, and no configuration is reset.

**Rules:**
- Every file-copy operation MUST check for existence first; if the target file exists, skip and log.
- Every symlink creation MUST check for existence first; if the link exists, skip and log.
- Incremental docs (README, INDEX, TODO, DAILY_ACTIVITIES) are **appended**, never replaced.
- The interactive question flow (8 questions — see D-25) MUST be re-entrant: partial scaffold runs
  that were interrupted can be resumed without damage.

### IV. Zero-Trust on Secrets

No credential, token, API key, password, or secret of any kind ever enters the codebase — not in
source files, not in templates, not in domain profiles, not in generated scaffold output.

**Rules:**
- `.secrets/` directories MUST appear in `.gitignore` by default in every generated project.
- Templates and profiles MUST reference secrets only via environment variable names or Vault/SSM
  path patterns (e.g., `${MY_API_KEY}`, `ssm://<path>`), never literal values.
- Any PR that introduces a literal secret pattern MUST be blocked and flagged as a critical finding.
- Domain profiles that describe deployment, CI/CD, or cloud integrations MUST include a
  "Secrets Management" subsection referencing env vars or external secret stores.

### V. Docs as First-Class Citizens

Operational documentation (`README.md`, `INDEX.md`, `TODO.md`, `DAILY_ACTIVITIES_*.md`,
`SESSION_REPORT_*.md`) is living, incremental work product. It MUST never be silently overwritten.

**Rules:**
- Scaffold MUST append to existing docs, never replace them.
- Session-scoped files (prefixed with date, e.g., `DAILY_ACTIVITIES_2026-03-05.md`) are immutable
  once the session closes — new sessions create new files.
- `TODO.md` and `INDEX.md` are canonical project state registers; changes to project structure MUST
  be reflected there within the same working session.
- Template files in `.specify/templates/` are the writable source; deployed copies in child projects
  are outputs — treat them accordingly.

### VI. Extensibility over Perfection

Domain profiles grow by extension, not by proliferation. Adding capability means adding a section to
an existing profile file, not creating a new file per concern.

**Rules:**
- Review checklists and runbooks are sections within the relevant domain profile (e.g., a
  `## Review Checklist` section inside `devops-security.md`) — not standalone files (see D-24).
- The total number of interactive scaffold questions is fixed at **8** (see D-25). New requirements
  MUST fit within or replace existing questions, not expand the flow arbitrarily.
- New domain profiles require a decision record (D-nn) before creation.
- Complexity MUST be justified: if a requirement can be satisfied with a section, a standalone file
  is prohibited.

## Scaffold Architecture

The `scripts/scaffold.py` interactive flow is the authoritative entry point for child project
generation. Its 8-question contract is:

| # | Question | Output |
|---|----------|--------|
| 1 | Project name | Directory name, README title |
| 2 | Project description | README, constitution |
| 3 | Primary language/stack | pyproject / package.json scaffold |
| 4 | Target domain | Domain profile selection seed |
| 5 | Git remote URL | `.git/config`, symlinks |
| 6 | VS Code workspace name | `.code-workspace` |
| 7 | Author / team | README, license headers |
| 8 | Domain profile selection | [1] domain only · [2] all · [3] manual select |

This table is normative. Changes require a D-nn decision record and a SPECKIT_SYNC_DATE bump.

## Governance

This constitution supersedes all other documented practices, ad-hoc conventions, and README-level
guidelines within the **a-default-project** template repository. In the event of conflict, the
constitution takes precedence.

**Amendment procedure:**
1. Open a session debate file (`DEBATE-<topic>.md`) documenting the motivation and alternatives.
2. Record the decision as a D-nn entry in the session record.
3. Update this constitution with the new or revised content.
4. Increment `CONSTITUTION_VERSION` following semantic versioning:
   - **MAJOR** — principle removed, renamed, or fundamentally redefined (breaking governance change).
   - **MINOR** — new principle or section added; existing principle materially extended.
   - **PATCH** — wording clarification, typo fix, non-semantic refinement.
5. Update `SPECKIT_SYNC_DATE` in `scripts/lib/config.py` if scaffold output is affected.
6. Include a migration note for any child projects already generated from this template.

**Compliance:**
- All pull requests touching `.specify/`, `.github/agents/`, `.github/prompts/`, or
  `scripts/scaffold.py` MUST include a constitution compliance check in the PR description.
- Agents operating on this repository MUST read this constitution before executing plan or spec tasks.
