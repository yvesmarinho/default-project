# GitHub Copilot - Regras Obrigatórias para este Projeto

## 🚫 REGRA ABSOLUTA: NUNCA USE `cat << EOF` OU `echo >>`

### ❌ PROIBIDO (Nunca fazer isto):
```bash
cat > arquivo.txt << 'EOF'
conteúdo
EOF

echo "conteúdo" >> arquivo.txt
```

### ✅ OBRIGATÓRIO (Use estas ferramentas):
1. **`create_file`** - Para criar novos arquivos
2. **`replace_string_in_file`** - Para editar arquivo existente
3. **`multi_replace_string_in_file`** - Para múltiplas edições

## Exemplos Corretos

### Criar arquivo novo:
```python
create_file(
    filePath="/path/to/file.txt",
    content="conteúdo aqui"
)
```

### Editar arquivo existente:
```python
replace_string_in_file(
    filePath="/path/to/file.txt",
    oldString="... 3 linhas antes\nconteúdo antigo\n... 3 linhas depois",
    newString="... 3 linhas antes\nconteúdo novo\n... 3 linhas depois"
)
```

### Múltiplas edições:
```python
multi_replace_string_in_file(
    explanation="Descrição do que está sendo feito",
    replacements=[
        {
            "filePath": "/path/file1.txt",
            "oldString": "...",
            "newString": "..."
        },
        {
            "filePath": "/path/file2.txt",
            "oldString": "...",
            "newString": "..."
        }
    ]
)
```

## Motivos desta Regra

1. **Auditabilidade** - Todas as mudanças aparecem nos diffs do git
2. **Segurança** - Impossível injetar comandos maliciosos
3. **Integridade** - Verificação sintática antes de aplicar
4. **Rastreabilidade** - Controle total sobre o que foi alterado
5. **Permissões** - O Copilot tem permissão total para usar as ferramentas

## Ferramentas Permitidas para Terminal

Usar `run_in_terminal` APENAS para:
- ✅ Executar comandos (git, tests, builds)
- ✅ Verificar status
- ✅ Ler output de comandos
- ❌ Nunca para criar/editar arquivos

## Checklist para Implementação

- [ ] Revisar cada tarefa
- [ ] Se cria arquivo novo → use `create_file`
- [ ] Se edita arquivo → use `replace_string_in_file`
- [ ] Se múltiplas edições → use `multi_replace_string_in_file`
- [ ] Nunca usar `cat`, `echo`, `tee`, `sed` para manipular arquivos
- [ ] Terminal apenas para executar, não para criar

## 🚫 REGRA ABSOLUTA: SEMPRE USE SHELL SCRIPT PARA GIT COMMITS

### ❌ PROIBIDO (Nunca fazer isto):
```bash
# NUNCA usar git commit direto
git commit -m "mensagem"

# NUNCA usar run_in_terminal para commits
run_in_terminal(command="git commit -m 'mensagem'")
```

### ✅ OBRIGATÓRIO (Use este procedimento):
```bash
1. Criar arquivo de mensagem:
   create_file(
       filePath="COMMIT_DESCRIÇÃO.txt",
       content="Mensagem estruturada..."
   )

2. Executar shell script:
   ./scripts/commit-k8s-revision.sh COMMIT_DESCRIÇÃO.txt
```

### Exemplo Correto:
```python
# 1. Criar arquivo de commit
create_file(
    filePath="/path/COMMIT_PHASE3.txt",
    content="PHASE 3: Complete Kubernetes...\n\nFILES ADDED:..."
)

# 2. Executar script (via run_in_terminal com isBackground=false)
run_in_terminal(
    command="./scripts/commit-k8s-revision.sh COMMIT_PHASE3.txt",
    explanation="Fazer commit usando shell script",
    isBackground=false
)
```

## Por que esta regra?

1. **Auditoria** - Shell script registra data, hora, autor
2. **Consistência** - Mensagens estruturadas em arquivo (não na CLI)
3. **Rastreabilidade** - Preview das mudanças antes de confirmar
4. **Controle** - Confirmação interativa (s/n) no script
5. **Documentação** - Arquivo `.txt` fica no histórico para referência

## Fluxo Correto de Commit

```
1. Stage files → git add arquivos.txt
2. Create commit message → create_file COMMIT_*.txt
3. Execute script → ./scripts/commit-k8s-revision.sh COMMIT_*.txt
4. Confirm interactive prompt → "s" (yes)
5. Verify commit → git log --oneline -5
```
